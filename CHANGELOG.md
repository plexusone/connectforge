## [v0.6.0] - 2026-10-25

### Highlights

- Egress hardening: link-local and cloud metadata addresses are refused whatever the policy, IPv6 forms that embed an internal IPv4 address are refused, and a base transport's TLS dialer can no longer bypass the address check
- Reconnect fails closed: a replacement credential must be shown to belong to the connection's account, unless the auth method declares that accounts cannot be identified
- Superseded credential versions are removed on swap, and stored health no longer carries provider headers, URLs or resolved addresses
- Breaking changes for `AllowPrivate` policies, providers that return no account ID, and custom `CredentialStore` implementations; see the upgrade guide

### Breaking

- `egress.Policy.AllowPrivate` no longer allows link-local addresses (`169.254.0.0/16`, `fe80::/10`) or cloud metadata addresses; they are refused whatever the policy says
- The egress address check refuses IANA special-purpose ranges that are not public destinations (such as `0.0.0.0/8`, `192.0.0.0/24`, `198.18.0.0/15`, `240.0.0.0/4` and the documentation ranges) and IPv6 addresses that embed an internal IPv4 address (NAT64, IPv4-compatible, 6to4, Teredo) or are site-local
- `egress.Client` clears `DialTLSContext`, `DialTLS` and `Dial` on the cloned `Policy.Transport`; TLS settings come from its `TLSClientConfig` only
- `Service.Create` refuses a credential whose validation returns no account ID, and `Service.Reconnect` returns `ErrAccountUnknown` when either the provider's or the connection's account ID is missing, unless the auth method sets `AccountUnverifiable`
- `apikey.New` requires an `AccountIDPath` (in `Verify` or `Account`) unless the auth method is `AccountUnverifiable`
- The `CredentialStore.SwapCredential` contract now requires removing versions older than the one installed, in the same operation
- `Health.LastError` holds only a provider's classified refusal (provider, class, status and a bounded request ID) or the provider and the failure's class; the full error is in the audit event

### Upgrade Guide

- Replace `AllowPrivate: true` with `AllowPrefixes` listing only the ranges a development or test setup needs, such as `netip.MustParsePrefix("127.0.0.0/8")`; a test destination on a link-local or metadata address must move to another address
- For a provider that cannot name the account a credential belongs to, set `AccountUnverifiable: true` on its `provider.AuthMethod`; otherwise make its `Validate` return `AccountID` (for `apikey`, set `AccountIDPath`)
- Connections stored without an account ID under a method that is not `AccountUnverifiable` cannot be reconnected (`ErrAccountUnknown`); connect them again as new connections and move their bindings
- Custom `CredentialStore` implementations: delete versions older than `next.Version` in `SwapCredential`, atomically with installing it
- Base transports that customised `DialTLSContext`, `DialTLS` or `Dial`: move TLS settings, including client certificates, into `TLSClientConfig`
- Code or dashboards that parsed `Health.LastError` for detail: read the audit event's reason instead

### Security

- The dial-time address check only unmapped IPv4-mapped IPv6 addresses, so an IPv6 address embedding an internal IPv4 address in another form passed: a NAT64 address such as `64:ff9b::a9fe:a9fe`, which a DNS64/NAT64 gateway translates to `169.254.169.254`, an IPv4-compatible address such as `::127.0.0.1`, and 6to4 and Teredo addresses. Several IPv4 special-purpose ranges were also allowed. The check now requires a global unicast, non-private address, judges a well-known-prefix NAT64 address by the IPv4 address it embeds, and refuses the special-purpose ranges that are not public destinations
- `Policy.AllowPrivate` turned off every address check, so a deployment that set it to reach an internal mock could also reach `169.254.169.254`, `fd00:ec2::254` and other cloud metadata endpoints. Link-local and metadata addresses, and IPv6 forms that embed one, are now refused whatever the policy
- `egress.Client` cloned `Policy.Transport` and replaced only `DialContext`. When the base transport set `DialTLSContext` or `DialTLS`, `net/http` used it for HTTPS instead, so the address check never ran and a provider host resolving to a loopback, private or metadata address was reached. These dialers are now cleared, so TLS is negotiated over a connection made by the checked dialer
- `Reconnect` refused a credential for a different account only when both the stored and the newly validated account IDs were present. When the provider returned no account ID, a credential for any account was installed under the existing connection, so every consumer bound to it started reading another account. The check now fails closed
- `SwapCredential` kept every earlier ciphertext until the connection was disconnected or deleted, so a later compromise of the encryption key would expose every replaced credential, including one replaced because it was suspected leaked. Older versions are now removed in the same operation (in a transaction in `sqlstore`, under the lock in `memstore`, which also zeroes the removed ciphertext)
- `Test` stored the full validation error in `Health.LastError`, which anyone who may view the connection reads: a provider's request-ID header verbatim and unbounded, and for network or egress failures the request URL and resolved address, including internal addresses. `provider.Classify` now keeps at most 128 printable ASCII characters of the request ID, and health records only the classified refusal or the failure's class

### Added

- `egress.Policy.AllowPrefixes`: the specific non-public ranges a development or test setup may reach; link-local and metadata addresses are refused even when listed
- `provider.AuthMethod.AccountUnverifiable` and `connectforge.ErrAccountUnknown`; a reconnect that proceeds without comparing accounts records `account=unverified` in its audit event

### Changed

- The broker builds one egress client per set of manifest hosts and hands out copies that share its transport, so connections are pooled; previously every validation and `HTTPClient` call built a new transport that was never closed, growing goroutines, file descriptors and provider connections

### Deprecated

- `egress.Policy.AllowPrivate`: list only the ranges a development setup needs in `AllowPrefixes`

### Documentation

- Connections, providers, security, storage and using-connections guides and the TRD describe the egress address rules, `AllowPrefixes`, the fail-closed account check, credential version removal and the bounded health message

### Tests

- Blocked-address table for special-purpose and IPv4-embedding IPv6 addresses, base-transport dialer replacement, shared broker transport, account checks on create and reconnect, bounded request IDs and health messages, and superseded-version removal in both stores

## [v0.5.0] - 2026-10-21

### Highlights

- Token sources: a provider can have a stored key, such as a service account key, exchanged for short-lived access tokens that the broker mints, keeps and replaces
- Nothing new is stored: a token is derived from the credential, so a refresh needs no lease
- No breaking changes

### Added

- `provider.TokenSource` and `provider.AccessToken`: an optional provider capability that exchanges the stored credential for an access token through the egress-restricted client
- `Broker.HTTPClient` authenticates with minted tokens for a provider that implements `TokenSource`; a token is kept until `provider.TokenExpiryMargin` before it expires, concurrent requests share one exchange, and a failed exchange is not kept
- `provider.NewTokenTransport` and `provider.NewTokenClient` apply the same rule outside the broker, for a provider's `Validate`
- `provider.ErrTokenSourceOnly`, returned by `Authenticate` for a credential used through a token source

### Documentation

- The TRD, providers, using, security and index guides and the README describe token sources and their limits

### Tests

- Token reuse, expiry margin, tokens without an expiry, failed and empty exchanges, concurrent requests sharing one exchange, and create, validate and use through the broker with a token source

## [v0.4.0] - 2026-10-20

### Highlights

- Guided setup: an auth method lists the steps a person follows to create a credential at the service, with links
- Rotation modes: an auth method describes how its credential is replaced, manual or automatic, with the extra permissions and risks of each
- Credential expiry reported by a provider is recorded in the connection's health
- No breaking changes

### Added

- `provider.SetupStep` and `AuthMethod.Setup`: ordered steps with a detail, an `https` link and the rotation modes each applies to
- `provider.RotationMode`, `AuthMethod.Rotation` and `AuthMethod.RotationMode`, with the mode keys `RotationManual` and `RotationAutomatic`; a mode carries extra scopes, risks, an expiry in days and whether it is recommended
- `Manifest.Validate` checks setup steps and rotation modes: `https` links, a key and label per mode, no duplicate modes, at most one recommended, and steps naming only listed modes
- `provider.Result.ExpiresAt` and `Health.CredentialExpiresAt`: `Create`, a successful `Test` and `Reconnect` record a credential's expiry on the sealed credential and in health
- `apikey.Request.ExpiresAtPath` reads a token's expiry from the verification response as an RFC 3339 timestamp; an unparseable value leaves it unknown

### Documentation

- The providers guide describes setup steps, rotation modes and expiry; the host integration guide covers guiding a person through connecting; the lifecycle, using and security guides cover expiry and rotation
- The security guide's known limitations are up to date

### Tests

- Manifest setup steps and rotation modes, and reading and recording credential expiry

## [v0.3.0] - 2026-10-13

### Highlights

- The module is renamed from connectionforge to connectforge

### Changed

- **Breaking:** the module path is `github.com/plexusone/connectforge` and the package is `connectforge`
- **Breaking:** the Ent tables are prefixed `connectforge_` and the credential purpose is `connectforge.credential`; a deployment with data from an earlier version renames its tables and re-seals credentials, or reconnects them
- The test database environment variable is `CONNECTFORGE_TEST_POSTGRES_DSN`

## [v0.2.0] - 2026-10-13

### Highlights

- `Reconnect` replaces a connection's credential without creating a new connection, so what is bound to it keeps working; the new credential is validated first and must belong to the same account
- Bindings are managed through the service: `Bindings` lists what depends on a connection, and `Bind` and `Unbind` record it, so a disconnect can show what it would stop
- No breaking changes

### Added

- `service.Reconnect`: validates the new credential with the provider before storing anything, refuses one for a different account with `ErrAccountMismatch`, writes a new credential version, and returns the connection to `connected` with fresh health. It recovers a connection whose sealed credential can no longer be read, and revives a disconnected one
- `service.Bindings`, `Bind` and `Unbind`, authorized as view, use and use, with a `binding.changed` audit event
- `ErrAccountMismatch`

### Documentation

- The user guide covers reconnecting and bindings

## [v0.1.0] - 2026-10-13

### Highlights

- Manage a tenant's connections to external services without handing callers a secret: a broker returns an authenticated `*http.Client` that provider SDKs accept, and credentials are sealed at rest
- Secrets cannot leak by construction: `Secret` prints as `[redacted]` in every format verb, JSON, text and `slog`, errors carry a status and a request ID but never a body, and a test confines `Reveal` to the broker and providers
- Ports and adapters: encryption, authorization, audit, leasing and deployment secrets are interfaces the host supplies, so the module imports no key manager, secret manager or application framework
- Ent-backed SQL store for SQLite and PostgreSQL that a host composes on its own database, with every owned table keyed on `owner_id` and a per-transaction hook for row-level security
- Not externally audited. Static API-token connections only; GitHub App, OAuth with refresh, and credential replacement follow

### Security

- Tokens are never present in a connection, an audit event or an error: a leak test pushes recognizable tokens through create, test and disconnect and checks every output
- A credential that cannot be read or decrypted makes a connection unusable; there is no fallback
- Every store method is scoped by owner, and a record of another owner is reported as not found

### Added

- Core model: `Connection`, versioned `Credential`, `Grant`, `Binding`, `Principal`, `Consumer` and `Use`, with a lifecycle (`pending`, `connected`, `needs_attention`, `disconnected`, `revoked`) kept separate from observed `Health`, and a transition table every store enforces
- `Secret` type that redacts itself in `String`, `GoString`, `Format`, `MarshalJSON`, `MarshalText` and `slog`, copies on construction and `Reveal`, and can be cleared
- Ports for stores, `Cryptographer`, `Authorizer`, `Auditor`, `Leaser` and `SecretSource`, with audit event types; credentials are sealed with additional data binding owner, connection and version
- `store/memstore`, an in-memory store and leaser, and the `store/storetest` and `cryptotest` conformance suites covering owner isolation, compare-and-swap under concurrency, transitions, cascade on delete and leases
- `sqlstore`: Ent-backed store and leaser for SQLite and PostgreSQL with `connectforge_` tables, `owner_id` on every owned table, conditional updates and unique indexes that decide races, a host `TxHook`, and `Tables()` for the host's tenancy policy
- `provider`: the provider interface, a declarative `Manifest` (fields, scopes, base URLs, help), a registry, versioned credential material, and `Classify`, which maps HTTP refusals to typed errors with the status and request ID
- `provider/apikey`: a configurable static-token provider that sets the token header, verifies it against a manifest-named endpoint, and discovers the account and scopes from the response by path
- `egress`: an HTTP client that allows only the manifest's hosts over HTTPS, refuses redirects to another host, and refuses private, loopback, link-local and shared addresses after DNS resolution
- `broker`: `HTTPClient` checks authorization and state, unseals the credential once, and returns a client that authenticates a copy of each request; also `Seal`, `Unseal` and `ProviderClient`
- `service`: `Create` (validates before storing anything), `Get`, `List`, `Rename`, `Test` and `Disconnect`, each authorized and audited, with a permanent failure moving a connection to `needs_attention` and a transient one changing only health

### Documentation

- MkDocs site with a getting-started page and a user guide covering connections and their lifecycle, using a connection, writing a provider, integrating with a host, storage and security
- Release notes for v0.1.0, and PRD, TRD, plan and roadmap under `docs/specs/initiatives/INIT-CONNECTFORGE-001`, with agent guidance in `AGENTS.md`
