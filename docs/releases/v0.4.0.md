# v0.4.0

**Release Date:** 2026-10-20

## Highlights

- **Guided setup.** An auth method can list the steps a person follows to
  create a credential at the service, with links, so an interface can walk
  them through it instead of pointing at a help page.
- **Rotation modes.** An auth method can describe the ways its credential is
  replaced, manual or automatic, with the extra permissions and risks of each,
  so a person chooses with the trade-offs in view.
- **Credential expiry.** When a provider reports when a credential stops
  working, the service records it in the connection's health.
- **No breaking changes.**

## Guided setup and rotation modes

`AuthMethod` gains `Setup` and `Rotation`:

```go
provider.AuthMethod{
	Key: "api_token",
	Rotation: []provider.RotationMode{{
		Key: provider.RotationManual, Label: "Rotate it myself", ExpiryDays: 90, Recommended: true,
	}},
	Setup: []provider.SetupStep{
		{Title: "Open API tokens", URL: "https://dash.example.com/profile/api-tokens"},
		{Title: "Set the token to expire", Detail: "Choose an end date 90 days from today."},
	},
}
```

| Type | Fields |
|------|--------|
| `SetupStep` | `Title`, `Detail`, an `https` `URL`, and the `Rotation` modes it applies to (empty: all) |
| `RotationMode` | `Key`, `Label`, `Description`, extra `Scopes`, `Risks`, `ExpiryDays`, `Recommended` |

- `RotationManual` and `RotationAutomatic` are the mode keys a host may act on.
  A host that does not implement a mode does not offer it.
- `AuthMethod.RotationMode(key)` looks a mode up, for checking a person's
  choice.
- `Manifest.Validate`, run when a provider is registered, checks the guidance:
  setup links are `https`, each mode has a key and a label, no mode is listed
  twice, at most one is recommended, and a step names only listed modes.
- connectforge describes the modes; the host keeps the person's choice, for
  example in the connection's `Metadata`.

## Credential expiry

- `provider.Result.ExpiresAt` reports when a credential stops working.
- `Create`, a successful `Test` and `Reconnect` record it on the sealed
  credential and in `Health.CredentialExpiresAt` (`credentialExpiresAt` in
  JSON).
- The `apikey` provider reads it from the verification response through
  `Request.ExpiresAtPath`, as an RFC 3339 timestamp. A missing or unparseable
  value leaves the expiry unknown and does not fail validation.

```go
Verify: apikey.Request{Path: "/client/v4/user/tokens/verify", ExpiresAtPath: "result.expires_on"},
```

```bash
go get github.com/plexusone/connectforge@v0.4.0
```

## Known limitations

- **Rotation is described, not performed.** connectforge does not replace
  credentials on a schedule; a host that offers automatic rotation
  implements it.
- **Nothing warns before an expiry.** The expiry is recorded; scheduled
  validation and warnings are not implemented.
- **Everything in the earlier limitations** still applies: static API tokens
  only, and a disconnect does not require acknowledging bindings.
