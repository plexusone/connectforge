# v0.6.0

**Release Date:** 2026-10-25

## Highlights

- **Egress refuses more of what a server should never reach.** Link-local and
  cloud metadata addresses are refused whatever the policy says, IPv6 forms
  that embed an internal IPv4 address are refused, and a base transport's TLS
  dialer can no longer bypass the address check. `AllowPrefixes` replaces the
  all-or-nothing `AllowPrivate`.
- **Reconnect fails closed.** A replacement credential must be shown to belong
  to the connection's account, unless the auth method declares that accounts
  cannot be identified.
- **Replaced credentials are gone.** Swapping a credential removes the older
  versions in the same operation.
- **Health shows less.** `Health.LastError` keeps a provider's classified
  refusal and otherwise only the failure's class; the full error is in the
  audit event.
- **Breaking changes** for `AllowPrivate` policies, providers that return no
  account ID, and custom `CredentialStore` implementations. See
  [Upgrading](#upgrading).

## Security fixes

### Egress address check

| Before | Now |
|--------|-----|
| Only IPv4-mapped IPv6 addresses were unmapped before the check | A well-known-prefix NAT64 address (`64:ff9b::a9fe:a9fe`, which a DNS64/NAT64 gateway translates to `169.254.169.254`) is judged by the IPv4 address it embeds; IPv4-compatible (`::127.0.0.1`), 6to4, Teredo, local-use NAT64 and site-local addresses are refused |
| Several IPv4 special-purpose ranges were allowed | `0.0.0.0/8`, `192.0.0.0/24`, `198.18.0.0/15`, `240.0.0.0/4`, the broadcast address and the documentation ranges are refused; only global unicast, non-private addresses pass |
| `AllowPrivate` turned off every address check | Link-local (`169.254.0.0/16`, `fe80::/10`) and cloud metadata addresses (such as `fd00:ec2::254` and `100.100.100.200`), and IPv6 forms that embed one, are refused whatever the policy |
| `egress.Client` replaced only `DialContext` on the base transport | `DialTLSContext`, `DialTLS` and `Dial` are cleared too, so `net/http` cannot use a TLS dialer that skips the check |

The last row closed a bypass: when `Policy.Transport` set `DialTLSContext` or
`DialTLS`, HTTPS connections used it instead of the checked dialer, and a
provider host resolving to a loopback, private or metadata address was
reached. TLS settings, including client certificates, still come from the base
transport's `TLSClientConfig`.

### Account check on reconnect

`Reconnect` refused a credential for a different account only when both the
stored account ID and the newly validated one were present. When the provider
returned none, for example an `apikey` provider without an `AccountIDPath`, the
check was skipped and a credential for any account was installed under the
existing connection, so every consumer bound to it started reading another
account.

Now:

- `Create` refuses a credential whose validation returns no account ID.
- `Reconnect` refuses with the new `ErrAccountUnknown` when either the
  provider's or the connection's account ID is missing.
- An auth method whose provider cannot name accounts opts out with the new
  `AuthMethod.AccountUnverifiable`. A reconnect that then cannot compare
  accounts proceeds, and its audit event carries `account=unverified`.
- Accounts named on both sides must still match (`ErrAccountMismatch`).
- `apikey.New` requires an `AccountIDPath`, in `Verify` or `Account`, unless
  the method is `AccountUnverifiable`.

### Superseded credentials removed

`SwapCredential` inserted the new credential version and kept every earlier
ciphertext until the connection was disconnected or deleted. Each `Reconnect`
left the replaced credential sealed in storage, so a later compromise of the
encryption key would expose every historical credential, including one
replaced because it was suspected leaked but could not be revoked at the
provider.

`SwapCredential` now removes the older versions in the same operation: in a
transaction in `sqlstore`, and under the lock in `memstore`, which also zeroes
the removed ciphertext. Concurrent swaps are still decided by the version check
and the unique index.

### Health without provider or network detail

`Test` stored the full validation error in `Health.LastError`, which anyone who
may view the connection reads. A provider's refusal embedded its request-ID
response header verbatim, with no limit on length or content, and a network or
egress failure carried the request URL and the resolved address, including
internal addresses that an egress refusal named.

`provider.Classify` now keeps at most 128 printable ASCII characters of the
request ID. `Test` records a provider's classified refusal (provider, class,
status and the bounded request ID) and, for any other failure, only the
provider and the failure's class, such as `connectforge: transient failure`.
The full error is still in the audit event's reason.

## Other changes

- **One egress transport per provider.** The broker built a new egress client,
  and so a new `http.Transport`, for every validation and every `HTTPClient`
  call, and never closed them. Repeatedly testing a connection could grow the
  server's goroutines and file descriptors without bound. The broker now builds
  the restricted client once per set of manifest hosts and hands out copies
  that share its transport; a caller's change to its copy, such as its timeout,
  does not affect other callers.
- **Deprecated:** `egress.Policy.AllowPrivate`. List only the ranges a
  development setup needs in `AllowPrefixes`.

## Upgrading

### 1. Replace `AllowPrivate` with `AllowPrefixes`

A policy with `AllowPrivate` set no longer reaches link-local or cloud metadata
addresses, and every policy now refuses the special-purpose ranges above. List
only the ranges a development or test destination needs:

```go
// Before
policy := egress.Policy{Hosts: hosts, AllowPrivate: true, AllowHTTP: true}

// After
policy := egress.Policy{
	Hosts:         hosts,
	AllowPrefixes: []netip.Prefix{netip.MustParsePrefix("127.0.0.0/8")},
	AllowHTTP:     true,
}
```

A test fake listening on a link-local or metadata address must move to another
address; no setting reaches those. Keep `AllowPrefixes`, `AllowPrivate` and
`AllowHTTP` off in production.

### 2. Configure TLS through `TLSClientConfig`

If your `Policy.Transport` set `DialTLSContext`, `DialTLS` or `Dial`, those are
now cleared. Move TLS settings, including client certificates, into the base
transport's `TLSClientConfig`:

```go
base := http.DefaultTransport.(*http.Transport).Clone()
base.TLSClientConfig = &tls.Config{Certificates: []tls.Certificate{clientCert}}
policy := egress.Policy{Hosts: hosts, Transport: base}
```

### 3. Make every provider identify the account, or say it cannot

Without an account ID, `Create` now fails with `ErrAccountUnknown`.

- For an `apikey` provider, set `AccountIDPath` on the `Verify` request, or on
  an `Account` request when the verification response does not name the
  account:

    ```go
    apikey.New(apikey.Config{
    	Manifest: manifest,
    	Verify:   apikey.Request{Path: "/v1/me", AccountIDPath: "account.id"},
    })
    ```

- For a custom provider, return `Result.AccountID` from `Validate`.
- If the service has no way to name the account a credential belongs to, set
  `AccountUnverifiable: true` on that `provider.AuthMethod` in the manifest.
  Reconnects then replace the credential without the account proof and record
  `account=unverified` in the audit event.

### 4. Reconnect connections stored without an account ID

A connection created before this release without an account ID, under a method
that is not `AccountUnverifiable`, can no longer be reconnected: `Reconnect`
returns `ErrAccountUnknown`. Connect the service again as a new connection,
bind its consumers to it with `Bind`, then `Unbind` them from the old one and
`Disconnect` it. Handle
`ErrAccountUnknown` wherever you handle `ErrAccountMismatch`.

### 5. Custom `CredentialStore` implementations

The `SwapCredential` contract changed: besides installing `next` as the active
version, it must remove every version older than `next.Version` in the same
operation, so a superseded credential never outlives its replacement in
storage. Do both in one transaction, or under one lock.

### 6. Readers of `Health.LastError`

`LastError` no longer contains URLs, resolved addresses or unbounded provider
headers. Code or dashboards that parsed it for detail should read the reason
on the connection's audit events instead.

### 7. Update the module

```bash
go get github.com/plexusone/connectforge@v0.6.0
go mod tidy
```

## Known limitations

- **A restored database backup still holds old credentials.** Removal on swap
  covers the live store only.
- **The shared store test suite does not yet check version removal.** The
  bundled stores test it themselves; a custom store should add its own test.
- **Everything in the earlier limitations** still applies.
