# v0.5.0

**Release Date:** 2026-10-21

## Highlights

- **Token sources.** A provider whose credential is a key, such as a Google
  service account key, can have it exchanged for short-lived access tokens.
  The broker mints them, keeps them until shortly before they expire and
  replaces them, so a client that lives a while keeps working.
- **Nothing new is stored.** A token is derived from the stored credential, so
  a refresh needs no lease and no persistence.
- **The exchange stays inside egress policy.** It goes through the same
  restricted client as every other request.
- **No breaking changes.** Providers that do not implement `TokenSource` behave
  as before.

## Token sources

A provider opts in by implementing `provider.TokenSource`:

```go
type TokenSource interface {
	Token(ctx context.Context, hc *http.Client, m Material) (AccessToken, error)
}

type AccessToken struct {
	Type      string    // "Bearer" when empty
	Value     cf.Secret
	ExpiresAt time.Time // zero: used once, not kept
}
```

- The broker detects the interface by type assertion. Where it is present,
  `Broker.HTTPClient` authenticates each request with a token in place of
  calling `Authenticate`.
- `hc` is restricted to the manifest's hosts, so the manifest lists the token
  endpoint's origin beside the service's.
- A token is kept in the client until `provider.TokenExpiryMargin` (a minute)
  before it expires. Concurrent requests share one exchange. A failed exchange
  is returned and not kept, so the next request tries again.
- `provider.NewTokenTransport` and `provider.NewTokenClient` apply the same rule
  outside the broker; a provider uses `NewTokenClient` in `Validate` to call its
  service with the credential.
- A provider's `Authenticate` returns `provider.ErrTokenSourceOnly`.

## Upgrade notes

None. Providers written for earlier versions need no change.

## Known limitations

- **A token is kept per client.** Clients made for separate units of work
  each mint their own; the token endpoint's rate limits are generous but not
  unlimited.
- **A rejected token is not retried.** A request that fails because its token
  was revoked early fails; the next client mints a new one. The expiry margin
  covers the ordinary case.
- **Refresh tokens are still to come.** Single-flight refresh of a rotating
  refresh token, for OAuth, is not implemented.
- **Everything in the earlier limitations** still applies.
